# C# の規約

## コメント

comment-refactoring スキルの基準で書く・直す。要点は、変更の経緯は書かず今の設計判断・仕様判断を書く、装飾を付けない、変数のサマリーは一行、コードから読み取れる否定形を避ける（禁止事項・制約は否定形でよい）、今後の課題は `// TODO:` にとどめる。kizami の対象範囲（Legacy・AutoGenerated・生成された Compositor は対象外）はスキルの references/projects.md にある。

## 命名

- private フィールド：`_camelCase`（private static readonly も `_camelCase`）
- const：`UPPER_SNAKE_CASE`（ローカルの const も含む）
- public のフィールド・メソッド・プロパティ：`UpperCamelCase`
- 否定形の名前を使わない（`ignoreX`、`NonZero`、`Unvisited` など）
- SerializeField の名前を変えるときは、`FormerlySerializedAs` を付けて参照を保ったまま保存し直してから、属性を外す

## メンバー順

- 変数：const → static readonly → readonly → static → public → [SerializeField] private → private
- プロパティ：public → static → その他。インターフェース実装のプロパティも修飾子どおりに並べる
- コンストラクタ：static → public → protected → private
- メソッド：override → static → public → protected → private → インターフェース実装（末尾）
- Unity のメッセージ（Awake / Update など）は private メソッドとして扱う
