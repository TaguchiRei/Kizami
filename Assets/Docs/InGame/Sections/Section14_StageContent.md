## 前提の変化（2026-10-07、区間5 の完了時）

- 区間5で、崩落による撃破を作った（足場ごと 3m 以上の落下と、落ちてくるボクセルの塊）。値（高さ 3m、塊の速さ 3m/s・体積 0.5m³）は TestStage で決めた仮のもの。敵が通る所の上を崩したときの見え方は、ステージを作るときに確かめる（TestStage では、敵がプレイヤーの周りの螺旋に並ぶので、崩す所の下に自然に集まらなかった）

## ステージの構想（2026-10-16、ユーザー）

4 ステージは、町のステージシーンを共有する（一番よく使うシーン）。チュートリアルから順に作り、ステージごとに必要な地形とモデルを作る。ステージの構造が変わるだけで、基礎のシステムは共通にする。

### 基礎システム（画面の表示）

- 右上：会話のテキスト。ここで説明を行う
- 左上：プレイヤーのやったことをログとして流す。その上に、ステージの攻略目標と小目標を表示する。小目標は進行度で変わり、基本は対象の破壊で変わる
- ログの種類は、スキル発動（「スキル名 発動」）、通常攻撃（連続したら右に「×N」）、スキル発動可能の通知（チャージが届いた段階）、エネルギー消費の通知（スキル発動の直後に消費量）、敵を倒した通知（連続したら「×N」）の 5 つ
- 「×N」でまとめるのは、通常攻撃と敵を倒した通知だけ。別のログが挟まったら新しい行にして、数を 1 から数え直す（Unity のコンソールのまとめ表示に近い仕組み）

### ステージ

ステージの流れは、Notion のメインシナリオに従う。チュートリアル → 殲滅 → 崩壊 → ボス戦（区間12）→ 到達。この区間は、この流れの順に作る。

| ステージ | 構想 |
|---|---|
| チュートリアル | 町の袋小路から始まる。UI 上部のポップアップで、移動・ジャンプ・ウォールラン・壁キックを順に案内し、操作したら次へ進む。袋小路を抜けるとボクセルの壁があり、スキルで壊す。進むと防護柵でふさがれた先に広場があり、敵（3 種）がいる。通常攻撃と倒壊による攻撃を説明する。マップは狭く、敵は最低限。死なない（失敗条件を空にする）。チュートリアル然とせず、通常マップの袋小路として置く |
| 殲滅 | 敵の生産の起点（生産施設のスポーン位置）を、置いた数だけ壊すとクリア。敵は今の出し直しの仕組みで出す（「際限なく」は比喩）。壊していく途中で、敵の生産を担うコアシステムの存在が分かる（崩壊へつながる） |
| 崩壊 | 敵の生産などを担うコアシステムを壊す。コアシステムは通常の方法では壊せないので、別の物の倒壊に巻き込んで壊す。あらかじめ壊した状態のモデル（通常のオブジェクト。ボクセルではない）を作り、その各部位が、壊れたボクセル片に当たると、全体から分離する。倒す物は、壊す対象に向かって斜めに置き、壊すと自然にぶつかるようにする。コアシステムを壊すとボスが登場する（ボス戦は区間12） |
| 到達 | 最終ステージ。中央の巨大な塔「天照塔」を倒して、外へ向かう道を作り、脱出地点にたどり着く。脱出地点のオブジェクトを壊すとクリア（到達エリアの判定は作らない）。道を作ると、その上に敵が出るので、倒しながら進む。道に出た敵を足止めする壊せる物を置いてもよい。破壊対象は少し傾けて置き、目標に向かって倒れやすくする。倒れる方向を決めるガイドのコライダーを置いてもよい。失敗条件は、プレイヤーの死亡と、制限時間切れ（腕輪のタイマーに相当） |

### 敵の置き方

- 敵は、移動のシステムだけを止めた仮想の敵にしてよい。動かずにプレイヤーを攻撃し、倒壊には巻き込まれる。手動で置く（スポーン位置に「動かない」設定を足す形）
- 巻き込んで壊す仕様（強度と衝突速度から倒れる角度を求め、倒れた側の箱で削る）は、今回は作らない。持ち越す

## 段階B（チュートリアル）の実装結果（2026-10-16）

### 決めたこと・変えたこと

- シーンは `Town`（共有の地形）、`Stage_Tutorial`（専用の中身）、`InGame`。`TutorialGroup` の主シーンが `Town`、追加シーンが `Stage_Tutorial` と `InGame`。ステージは常駐シーンの `_stages` へ登録した
- プレイヤーの数値は、C# の既定値ではなく `PlayerParameterData.asset` の値（歩き 20m/s、走り 25m/s、ジャンプ 4m、壁走り 30m/s で 10 秒、壁キックの水平 10m/s）。地形はこの値で決めた
- `StageData` に「固定スキル」と「開始時のチャージ量」を足した。チュートリアルは、スキル 3 つを固定し、開始時のチャージを 100 にした
- 壁を壊す区間のチャージは、切れる物から貯める案を、開始時のチャージ 100 に変えた。旧 `CuttableObject.prefab` は、スクリプトが壊れていて使えない（`MeshBreak::CuttableEnemy`）
- 壁（z=71）と防護柵（z=104）は、ビームの長さ 30m より離して、1 発で両方壊れないようにした
- 壁の破壊済みの割合は 0.15、防護柵は 0.05（ビーム 1 発で壊れる）。穴の下に低い段が残るので、ジャンプして抜ける
- 台本は 9 段階（移動 → ジャンプ → 壁走り → 壁キック → 壁を壊す → 柵を壊す → 敵を切って倒す → 足場を崩す → ゲートを壊す）

### 確認したこと

- アウトゲームの選択肢から入る、不死（HP 0 でも失敗にならない）、Retry、メニューへ戻る、クリア済みの表示と初回クリアの通貨、再入場でやり直せる
- 台本が最後まで進む。壁キックの二段（幅 10m の袋小路の左右の壁）で、高さ 7m の足場に登れる。通常のジャンプでは登れない

## 段階D（崩壊）の実装結果（2026-10-16）

### 決めたこと・変えたこと

- 破壊対象の共通の窓口に `IDestructionTarget`（`IsDestroyed` と、デバッグ表示へ書き足す `AppendStatus`）を足した。ボクセルの `DestructionTarget` と、新しい `CoreSystem` が実装する。`StageClearAdapter` は両方を集めて数え、`StageInitializer` の表示は `AppendStatus` を呼ぶ。台本の `TargetDestroyed` は、`IDestructionTarget` を実装したコンポーネントを指す（`MonoBehaviour` で受けて、使うときに型を見る）
- コアは普通のオブジェクト。`CoreSystem` の子に `CorePart` を並べる。`CorePart` は始めキネマティックで、`VoxelPiece` が付いた物が相対速度 2m/s 以上で当たったら、止めるのをやめて分離する。分離した部位が部位の数の 0.5 以上で `CoreSystem` が破壊済みになる。ビームや爆発は、`CorePart` に作用する経路がないので、コアは動かない
- 倒す物は、傾けた柱（`ToppleTower`）。ボクセルの分離は「一番大きい塊を残して、他を Rigidbody 付きで切り離す」ので、倒したい上の塊より大きな土台（広い台座）を同じパーツに含める。台座と傾けた柱を1つのモデルとしてベイクし、根元を切ると柱が的の側へ倒れる。傾きは 25°（12° では、切り口の面で立ったまま止まった）
- 的は柱から 7m 離す。近すぎると、倒れる前に当たって速さが足りず、分離しない
- 仮のコアは、2.9m の立方体8個（2×2×2）。シーンは `Town`（主）、`Stage_Collapse`、`InGame`。`CollapseGroup`・`CollapseStageData` を作り、常駐シーンの `_stages` の4番目に登録した。開始位置は (-150, 0, 20)。敵の移動範囲は殲滅と同じ大きさ
- 敵は、コアの左右に2か所（`EnemySquad_Defender5`、`EnemySquad_Finisher5`）。どちらも出現を保留し、台本で1段階目の入口と2段階目の入口に解放する。台本は2段階（敵を3体倒す → 柱を倒してコアにぶつける）で、2段階目の条件がコアの `TargetDestroyed`。文は `CollapseGuideTexts`

### 確認したこと

- 柱の根元を削ると、柱が倒れてコアに当たり、部位が 4/8 分離して STAGE CLEAR になる。台本の文の表示と、保留した敵の解放も動く

- `EnemySpawnCube`（EnemySpawn レイヤー）は、`Default` レイヤーとは衝突しない。コアの部位は `Default` レイヤー

### 見つけた問題・持ち越すこと

- 根元を削るのは、実行中のコードから球で削って確かめた。実際のビームや爆発での倒し方と、倒れる速さの調整はしていない

- 柱を倒す前に敵を3体倒さないと、2段階目の小目標が出ない。クリアは段階に関係なく、コアが壊れた時点
- アウトゲームの選択肢に「Collapse」が出るかは、画面では見ていない（番号で入った）

- 実際のビーム・爆発での倒し方と、倒れる速さは調整していない

### 確認したこと
