### デバッグ表示の出し入れの作り

- 出し入れの状態は、常駐シーンに置く小さな Adapter（名前の案：`DebugVisibilityAdapter`）が持つ。決めたキー（決めること #1）で切り替え、既定は隠す
- 隠している間は、`DebugGUI` のコンポーネントを無効にする（`OnGUI` が呼ばれなくなる）。`TimeScaleDebugInitializer`・`PlayerDebugInitializer` の自前の `OnGUI` と、`PlayerDebugInitializer`・`BossDebugInitializer` のキー操作は、出している間だけ動かす
- デバッグ用の Initializer は、ほかのコードから参照されない。出し入れの状態は、`DebugGUI` と同じく static のプロパティで読めるようにしてよい（デバッグ専用で、ゲームのルールではない為）。State にはしない
- 別の案として、出し入れを UsefulToolkit.Debugging の `DebugGUI` 自体の機能にする手もある。ほかのプロジェクトでも使えるが、ライブラリの変更になる。着手時にユーザーに聞く（決めること #2）
- アウトゲームに、上の表のほかにも昔のデバッグ用の表示や操作が残っていないかを、実機で見て一覧にして報告する。消すか残すかはユーザーが決める

### ヒットエフェクトの作り

- 通常攻撃とスキルの 2 か所から使うので、エフェクトを出す部品を 1 つ作る（名前の案：`HitEffectPlayer`）。インゲームのシーンに置き、`SoundPlayer` と同じく static の `Play(位置, 向き)` で呼べるようにする。プールした粒を使い回し、同じフレームに出す数に上限を付ける
- 見た目は決めること #3 による。VFX Graph はコードで組みにくいので、パーティクル（Shuriken）のプレハブを、エディタのスクリプト（uloop の execute-dynamic-code）で作ってもよい。光る粒には既存の加算マテリアル（`FinisherGlow.mat` など）を使えるか確かめる
- 当たった位置は、通常攻撃では、集めたコライダーのうちカメラに最も近いものの `ClosestPoint`（刃の中心から）を使う。向きはカメラから当たった点への向き

### 造山の作り

- `MoundEffect` の値を、石柱の半径・長さ・伸びる時間にする（名前の案：`_radius`・`_length`・`_growDuration`）。`SerializeReference` の型名を変えるとアセットが壊れるので、クラス名は `MoundEffect` のまま残す。アセットの値を入れ直す
- 長押しの仕組み（`SkillService` の `_moundSlot`・`_onMoundBegin`・`_onMoundEnd`・離したときの処理、`VoxelMoundState`、`MeleeCutService` の盛り中の判定）を消す
- 発動の流れ：`SkillService` は、ほかの単発のスキルと同じく、チャージを消費したら `PlayerSkillEffectEvents` に石柱の出来事を流す。ただし何にも当たらないときにチャージを減らさないよう、消費の前に「出せるか」を確かめる関数（Adapter のレイの判定）を受け取って呼ぶ
- `VoxelMoundAdapter`（名前を変えるなら `VoxelPillarAdapter`。変えるときはシーンの参照が外れないように `FormerlySerializedAs` などで保つ）が出来事を購読し、画面の中央（カメラの正面）からレイを飛ばして、当たった点と法線を求める
- 石柱は、当たった点を根元にして法線の向きへ伸びるカプセル（`CapsuleShape`）を、`_growDuration` の間に数回に分けて `Union` し、伸びるように見せる。根元は面の少し内側に埋める。ピースの範囲（`CreateVolume`）は石柱が収まる大きさにし、ピースの向きを法線に合わせる
- プールと「同時に 4 本、超えたら最も古いものを使い回す」は今の仕組みを残す
- ピースの物理（落ちるか、その場に留まるか）は今の盛ったピースと同じにする。壁から横に出た石柱が落ちてしまうなら報告する
