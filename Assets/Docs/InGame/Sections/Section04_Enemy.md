## 目的

湧き場所から出続ける雑魚敵を作る。切って倒すとチャージになり、敵の攻撃でプレイヤーの HP が 0 になると失敗する。
この区間が終わるとマイルストーンA（「切って溜める」までがつながる）になる。

## 関連する仕様

- 敵の出現：https://app.notion.com/p/3e91ea2aa7fa81de9e78d74221c216c8
- 失敗条件：https://app.notion.com/p/3e91ea2aa7fa813fb405e07c700a75b4

## 前提

- 敵は、パーツごとに分かれた軽量なメッシュ（全パーツを合わせて 2000 ポリゴン未満）を、パーツ単位で FK / IK で動かす。SkinnedMeshRenderer は使わない
- 敵の移動と FK / IK は `Time.deltaTime` を使う（スロー中は一緒に遅くなる）。Animator を使う場合、Update Mode は Normal にする
- 区間1で、被ダメージの窓口 `PlayerHealthService.ApplyDamage(int)`（ワープ中は軽減率を適用）と、HP の読み取り面 `IPlayerHealthState`（`RegisterOnHealthChanged` で HP が 0 になったことを受け取れる）を作った。`PlayerHealthService` は `PlayerInitializer` が具象型のまま `StandardPlayerControlCompositor` に DI 登録している

## MeshCut の制約（敵に関わるもの）

| 制約 | 影響 |
|---|---|
| `MeshDataCache` は `Start` の時点で自分の子孫にある `CuttableObject` だけを登録する。実行中に新しいメッシュを 1 つだけ登録する公開 API はない（`Initialize()` はすべてを登録し直す） | 実行中に `Instantiate` した敵は、そのままでは切れない。敵のプールは最初から `MeshDataCache` の子孫に置く、などの対応が要る |
| 切られたパーツは `DisableCutting()` で切れない状態になり、非アクティブになる | 敵を再利用するときは、切られたパーツを表示し直し、切れる状態に戻す必要がある |
| ストアの作り直し（`Rebuild`）で、切れない状態の `CuttableObject` は登録から外れる | 切られたパーツは `MeshId` を失うことがあるので、`SetRegisteredMesh` で戻すだけでは足りない場合がある |
| 刃をローカル空間へ移すときの拡大率は `localScale` を使う（区間2で確認） | パーツの親に拡大率を持たせると、切断面がずれる。拡大率はパーツ自身に持たせるか、メッシュに焼き込む |
| 近接切断の刃はカメラの位置を通る（区間2の決定） | 水平（0°）に振ると、カメラより低い部分は切れない。敵の大きさを決めるときに考える |

## 完了条件

- 敵が湧き場所から出続け、同時に存在する数が上限を超えない
- 敵がプレイヤーに近づいて攻撃し、HP が減る
- 敵を切ると倒れ、かけらがチャージになる
- 倒した敵が再利用されて出てきたとき、もう一度切れる
- HP が 0 になると失敗になる

## 詳細仕様で決めること

| # | 項目 | 案 |
|---|---|---|
| 1 | 敵を MeshCut に登録して使い回す方法 | 敵のプールを最初から `MeshDataCache` の子孫に置いて、`Start` で登録させる。再利用のときにパーツを切れる状態へ戻す API（元のメッシュの `MeshId` を保持して戻す など）を UsefulToolkit.MeshCut に足す。UsefulToolkit を変える場合はユーザーに確認する |
| 2 | 雑魚敵の攻撃 | 攻撃する方法（近接、射撃 など）と、その威力 |
| 3 | 敵を倒す条件 | どのパーツを切れば倒れるか、部位破壊で何が変わるか |
| 4 | 出現の仮の値 | 同時に存在する数の上限と、出現間隔 |
| 5 | 地形の変化 | ボクセルが削れて地形が変わったときの NavMesh の扱い |
| 6 | 失敗したあとの流れ | 仮にリトライのみ など |
| 7 | 敵から被ダメージの窓口へ届く経路 | DI のスコープは Compositor ごとに分かれ、InGame シーンからは StandardPlayerControl のスコープに登録した `PlayerHealthService` を受け取れない。常駐シーンの Root スコープへ移す、ダメージを Board 経由で渡す、などから選ぶ |

## 他プラットフォームへの対応

- 敵の処理にプラットフォームによる違いはない。スマホでは、同時に存在する数の上限を別の値にする可能性がある
