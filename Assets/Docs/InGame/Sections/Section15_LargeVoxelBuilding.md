区間の番号は識別用。区間15は 2026-10-09 に追加した区間で、区間9のあと、区間10の前に行う。区間10のダメージタイプの表で、各攻撃の強さと減衰率を、装甲への効き方と一緒に決められるようにする為。

## 目的

マップに置く大きな建物（ビルなど）を、削れるボクセルにする。1 階分をベイクして縦に積み重ね、素材ごとの強度で壊れ方を変え、階の上下のつながりが断たれたら倒す。倒れていない建物の傷は、敵の追跡範囲の外に出たら修復し、戻ったら当て直す。

## 前提

- 今のボクセルは、データと分離の判定がボリューム全体を扱う。大きな建物を 1 つのボクセルにすると、削るたびに全体の点を調べる（[LargeObjectVoxel.md](../../Voxel/LargeObjectVoxel.md) の「今のボクセルの重さ」）
- 敵は建物に上れない。傷を残す範囲は、区間4D の追跡範囲と同じ

## 完了条件

- レンガの壁を弱い攻撃で削ると、目地が深く削れてレンガの形が浮き出る。鉄筋コンクリートの柱は、コンクリートが崩れたあとに鉄筋が残る
- 階の柱を断つと、上の階がまとめて倒れ、下の敵を巻き込む。倒れた建物は地形として残り、敵がそれを避けて動く
- 傷を付けた階は、追跡範囲の外へ離れるとメッシュに戻り、戻ると同じ傷が戻る
- 階をたくさん積んだ建物を削っても、削る 1 回の時間が建物の高さで増えない

### 途中のこと：角ばりの問題の対策（2026-10-14）

B-7 の確認で、0.4m のボクセルでは厚さ 0.8m の外壁が筒のように丸まり、階の境目も V 字の溝に見えた。これへの対策を、次の順で調べた。

#### B-7a：Dual Contouring（159ef07 に入れ、B-7b-1 で取り除いた）

- `VoxelQualitySettings._smoothness` を足し、`SurfaceNetsJob` で Dual Contouring の点と今の点を混ぜた。対象は `SurfaceNetsJob.cs`・`VoxelPiece.cs`・`VoxelQualitySettings.cs`・`VoxelMeltSurface.cs`・`VoxelQuality_Building.asset`（滑らかさ 0 のまま）
- 効果はほとんど無い。0.8m 角の帯で、角の頂点の本来の角からのずれは 0.2m で 0.067m → 0.059m、0.4m で 0.083m。再メッシュ化は約 1.5ms 重くなる
- 効果が小さいので取り除いた（B-7b-1）

#### 丸く見える原因の切り分け

- ベイクの距離場は正確（角の外も正しいユークリッド距離）。`BuildingFloorTest` のベイクはもともと 0.2m
- 0.2m では形はほぼ四角（角の欠けは約 0.06m）。丸く見えたのは法線のせい。法線を 0.2m 間隔の中心差分から取る為、平らな面の頂点の法線まで角の向きが混ざり、0.8m の幅で円柱のように回る。メッシュの法線を面から取り直すと、柱は平らに見えた
- 0.4m では、部材が 2 セルしかなく、形そのものが 1 辺に頂点 1 つの八角形になる

#### 描き方を変える試作（段階1：見た目、159ef07）

Surface Nets の頂点をセルの中心に置くと、ボクセルを積んだ角ばった形になる（もとの Surface Nets は白黒のボリュームから角ばった形を作り、頂点をセルの中で動かして滑らかにする手法）。そこで頂点ごとに「角ばった位置」と「滑らかな位置」を持ち、頂点ごとの丸みでシェーダーが混ぜる。

| ファイル | 内容 |
|---|---|
| `EngineAdapterLayer/Voxel/Experimental/BlockSmoothMeshJob.cs` | `SurfaceNetsJob`（コミット済みの版）のコピー。頂点の位置はセルの中心、法線は滑らかな形のもの、UV1 の xyz は滑らかな位置までの差、w は丸み。距離を符号だけにして求める切り替え（白黒）を持つ |
| `EngineAdapterLayer/Voxel/Experimental/BlockSmoothRoundnessJob.cs` | 点ごとの丸み。読み込んだときの距離から変わった点を 1 とし、周りへ薄めて広げ、素材の強度ごとの倍率を掛ける |
| `EngineAdapterLayer/Voxel/Experimental/BlockSmoothPreview.cs` | 建物に付け、子のピースを試作のメッシュで描き直す。削る処理と当たり判定は今のピースのまま。F2：今の描画と切り替え、F3：丸みの決め方（全部角ばる・全部滑らか・壊した周りだけ）、F4：滑らかな位置の元（距離・白黒） |
| `Code/Shader/Building/BuildingPatternBlock.shader` | `BuildingPattern` のコピーに、位置の混ぜ方を足した物。丸みの無い所は三角形の面の向きで陰影を付ける。影のパスでは、丸みの無い所で法線の向きにずらさない（ずらすと角で自分に影を落とす） |
| `Data/Voxel/Experimental/VoxelQuality_Building02.asset` | 比べる為の 0.2m の品質設定 |

確認用のシーン `BuildingVoxelMeasure` に、`BuildingTest02`（x = 65、0.2m）を足し、2 棟に `BlockSmoothPreview` を付けた。置いた場所は `Kizami.EngineAdapter.Runtime` の中（`VoxelPiece.VolumeData` などが internal の為）。

結果

- 0.4m・0.2m とも、建物は角がくっきりした箱になり、階の境目の溝も消えた。「壊した周りだけ滑らか」で、建物は四角いまま削った穴だけ滑らかになる
- 白黒（距離を持たない）から求めた滑らかさは、距離からのものより少しでこぼこするが使える。データを素材の番号だけにする方式も、見た目の面では成り立つ
- 1 階分を 1 スレッドで全チャンク作る時間：今の Surface Nets 4.97ms（0.4m）・30.30ms（0.2m）、試作 5.31ms・32.18ms。メッシュの生成は軽くならない。丸みの計算はボリューム全体をやり直していて 2.28ms・14.10ms（変わった範囲に絞れば減らせる）。プレイ中にスクリプトから Job を呼んで計ったので、Burst が効いていたかは未確認

#### 試作の段階2：箱を組み合わせた当たり判定（70b6e12・4887892）

- `Experimental/BlockColliderJob.cs`：チャンクの中身の点を、x・y・z の順に伸ばせるだけ伸ばした箱にまとめる。箱は各点の ±半ボクセルで、角ばった描き方の形と一致する
- `BlockSmoothPreview` が、チャンクを作り直すときに箱も作り、チャンクの GameObject の BoxCollider に反映する（足りなければ足し、余りは無効にして使い回す）。今のピースの MeshCollider はそのまま残している

### 作業で分かったこと（コードや計画に効くもの）

- 建物のパーツのベイクは、内外の補正を 0 回にする（`VoxelBakeSettings.SignPassCount = 0`）。補正 1 回だと、接した箱がたくさん並ぶモデルで外の点まで内側になり、体積が 1.76 倍になった
- 素材の違う箱を重ねてはいけない。重なった所は距離の深い方の素材になる。鉄筋の周りのコンクリートは、鉄筋と重ならない 4 つの箱で組む（`BuildingFloorTest` の柱が手本）
- 建物の高さは、ステージの天井（`StageBounds/Ceiling`、TestStage では y = 25〜30）より低くする。天井を突き抜けて置くと、倒れて Rigidbody になった瞬間に天井から押し出され、跳ねたり宙に浮いたりする
- 部材の寸法と位置は 0.4m の倍数にし、モデルの原点に合わせて置く。格子はオブジェクト空間の 0.4m の倍数 + 0.2m に点を置く
- 素材の番号ごとの強度は `VoxelPiece.SetMaterials(VoxelMaterialEntry[])` で渡す。`VoxelModelLoader` は読み込みのときにモデルの素材の一覧から渡し、`VoxelBuilding` は読み込みの通知で階ごとのマテリアルの複製に差し替える
- 攻撃の強さは「普通の素材がちょうど今の半径で削れる値」（P = 1 + a × 半径）。届く範囲の半径は 半径 + 1 / a。減衰率 a は `VoxelDestructionAdapter` の設定値（既定 0.5）で、区間10で決め直す
- 温度は「その点の素材の融点を 1 とした値」で持つ。蒸発点の設定値（2）は融点に対する倍率になった
- `SurfaceNetsJob` はピースと液面（`VoxelMeltSurface`）の 2 か所から使う。入力を足したら両方を直す

### 組み込みの方針

- 試作（`Voxel/Experimental/`、`BuildingPatternBlock.shader`）は上乗せの形で、今のピースのメッシュと MeshCollider を裏で作り続けている。試作のコードはそのまま本採用にせず、`VoxelPiece` の描き方と当たり判定の作り方として組み込み直す
- 描き方は品質設定（`VoxelQualitySettings`）で切り替える。敵などの今の物は今の描き方のまま
- 角ばった描き方のメッシュ生成は、`SurfaceNetsJob` に組み込み、メッシュの生成を 1 か所にする。液面（`VoxelMeltSurface`）は今の描き方のまま
- 丸みは、読み込んだときの距離と比べる形をやめ、削る・加熱の処理で値が変わった点をその場で印にする。読み込んだときの距離の複製が要らなくなる。丸みは点ごとに byte で持ち、`Clone`・`ExtractComponent` で引き継ぐ
- シェーダーは `BuildingPattern` に位置と法線の混ぜ方を入れ、1 つにする。メッシュのままの階は UV1 が 0 なので、今と同じに描かれる
- 当たり判定は `VoxelColliderMode` に箱の種類を足す。分離で生まれるかけらは今の凸包のまま

## 計測の結果（2026-10-13、エディタ）

計測はユーザーの今の PC のエディタで、uloop から 1 回ずつ値を読んだ。シーンは `BuildingVoxelMeasure.unity`。

### 1 階分（40m × 40m × 高さ 4m）

| | 0.4m | 0.2m |
|---|---|---|
| 格子点（距離のメモリ） | 330,625（1.26MB） | 2,370,334（9.0MB） |
| 中身の点 | 13,065 | 104,543 |
| 表面のあるチャンク | 16 | 89 |
| 三角形 | 54,044 | 216,232 |
| CSG（球、半径 1〜4m） | 0.06〜0.08ms | 0.18〜0.23ms |
| 分離の判定 | 1.5〜2.0ms | 10.5〜12.0ms |
| 平面での切り分け | 27.2ms | 38.5ms |
| 削ったあとの再メッシュ化 | 3.2〜3.8ms | 3.7〜5.7ms |

- 削るたびに重いのは分離の判定で、0.2m は 0.4m の約 6 倍。0.2m では 1 回で 60fps の 1 フレームの大半を使う
- 平面での切り分けは、ボリュームを複製して両側を削るので、0.4m でも 27ms かかる

### 20 階を積んだ描画

| 配置 | SetPass | 描画の回数 | 三角形 | メモリの増え方 |
|---|---|---|---|---|
| メッシュの階、今のマテリアル | 21〜23 | 49〜61 | 2.4 万 | ― |
| メッシュの階、模様のシェーダー（ずらしなし・案a・案b・案c） | 21〜23 | 49〜61 | 2.4 万 | ― |
| ボクセルの階 0.4m | 22〜25 | 約 410 | 約 130 万 | 約 80MB |
| ボクセルの階 0.2m | 28〜29 | 約 1,900 | 約 480 万 | 約 400MB |

- 模様のずらし方の 3 案は、SetPass と描画の回数が同じだった。マテリアルの数が違っても SRP Batcher がまとめて描いている
- フレーム時間はエディタの処理で 1 回ごとに数 ms ぶれ、模様のシェーダーの毎ピクセルの重さは読み取れなかった。`FrameTimingManager` の GPU の時間は、エディタではどの配置も約 0.44ms で、測れていない。必要なら Profiler の GPU モジュールで確かめる

### 見た目

- 0.4m では、厚さ 0.4m の壁と床がボクセル 1 つ分の太さになり、角が丸まって筒のように見える
- 上下の階の境目に横の溝が見える。各階の距離場が、それぞれの上下の面で丸まる為
- 丸まった角では、投影する平面が法線で切り替わり、模様が曲がる
- 読み込んだボクセルの範囲が、メッシュより x で 0.05m、z で 0.02m ずれている。模様の周期を格子の原点にそろえるときに考える

- 削った階はチャンクごとの MeshRenderer になり、描画の数とメモリが増える。スマホと VR での重さは、15-1 の計測の値を残しておき、区間13で確かめる。低スペックの PC での重さも、ビルドできる段階で同じく確かめる
