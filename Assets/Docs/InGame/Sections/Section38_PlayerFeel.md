## 目的

通常攻撃・スキル・移動などのプレイヤーの行動に、腕のアニメーションとエフェクトを付け、当たったときにヒットストップを入れて手応えを出す。

## 計画書と今のコードの食い違い（2026-10-22 確認）

| # | 計画書の記述 | 実際のコード |
|---|---|---|
| 1 | `TimeScaleService` に短い時間の倍率を足せばヒットストップを作れる | `ITimeScaleController` は `SetScale` と `ResetScale`（1 に戻す）だけで、`SlowModeService` が直接呼ぶ。ヒットストップが同じ口を使うと、スロー中の倍率が 1 に戻って壊れる。仕様 9 で合成にする |
| 2 | 腕を置いてアニメーションを再生する | `ArmModel.prefab` は `AnimationTest.unity` にしか置かれていない。`ArmModel.fbx` のクリップは空で、リグは Generic |
| 3 | ワープのエフェクトを付ける | 短距離ワープはオミットと決まった（仕様 8）。`Warping` は突進の移動モード（`StartRush` が設定）で、`WarpDamageReduction` は突進中のダメージ軽減。消すものはない |
| 4 | （記述なし） | `StageFlowService.Pause` はポーズ前の倍率を `ITimeScaleState.Scale` から読んで保存する（[StageFlowService.cs:157](../../../Code/Scripts/Application/Stage/StageFlowService.cs:157)）。仕様 9 の合成後の値が `Scale` に入るので、ヒットストップ中にポーズすると 0 を保存し、解除後に止まったままになる。ポーズの前にヒットストップを取り消す |

## 作業計画で決めること・確認すること

- ヒットストップ中のスローの消費の止まり方：`SlowModeService.DrainAsync` は倍率が 0 以下の間は消費しない。1 回の止まりは約 0.05〜0.08 秒で、その分だけスローが少し長く続く。許容して変更しない案
- ポーズとの重なり：食い違い 4 のとおり、`ITimeScaleController` にヒットストップを取り消す操作を足し、`Pause` の先頭で呼ぶ案
- 仕様 8 の反映先：全体計画書と Notion の仕様書（ユーザーが内容を確認してから反映）

## 作業計画（2026-10-22 案、GO 待ち）

### 既存の機能で足りるもの
- 腕の IK：Unity 公式の Animation Rigging パッケージ（Two Bone IK Constraint）。未導入（`Packages/manifest.json` にない）。`OnAnimatorIK` は Humanoid 専用で、`ArmModel.fbx` は Generic のため使えない
- エフェクト：導入済みの VFX Graph（`Explosion.vfx` と `BlastEffect` が先例）

### 新しく作る型

| 型 | 層 | 今の区間の利用者 |
|---|---|---|
| `PlayerArmAdapter` | EngineAdapterLayer | 通常攻撃（IK の目標）、スキル 5 種、投擲、ウォールランの手。腕の Animator と IK を動かす口 |

`ITimeScaleController` に `RequestHitStop` と `CancelHitStop` を足し、`TimeScaleService` を直す。`PlayerParameterData` にヒットストップの長さと倍率を足す。State と Event は足さない。

### コミットの分け方

| # | 内容 | 確かめ方 |
|---|---|---|
| 1 | ヒットストップ。`TimeScaleService` の合成、`RequestHitStop` / `CancelHitStop`、`Pause` の先頭で取り消し、`MeleeCutAdapter` の「当たった」通知を `PlayerInitializer` で配線 | 敵・建物・装甲だけに当てた振りで止まる。スロー中・スロー終了直前に試して倍率が戻る。止まっている間にポーズして、解除後に動く |
| 2 | Animation Rigging の導入、腕のプレイヤーへの配置、`PlayerArmAdapter`、通常攻撃の IK（振る角度に追従） | 角度を変えて振ると腕が追う。スロー中も等速 |
| 3 | スキル 5 種のアニメーションの配線と、投擲のクリップ（Editor ビルダー）。突進は付けない | 各スキルと投擲で再生される。刀術は共通のクリップ |
| 4 | ウォールラン中に壁へ手を当てる | 壁走りで手が壁に付く |
| 5 | 斬撃の軌跡、スキル発動のエフェクト | 目視 |
| 6 | SE（区間36 の口） | 聞いて確かめる |

コミット 3 はスキルのクリップができてから着手する。できるまでは 4 を先に進める。

### 作業中に確かめること
- コミット 4：壁の位置と向きを渡せる元（`PlayerMovementAdapterBase` の接触情報など）。`PlayerMovementState` に壁の法線は無い。無ければ、Adapter 内で完結させる案を出す（基準2）
- コミット 1：ピースや装甲だけに当たった振りも拾えるよう、`MeleeCutAdapter.Swing` で「何かに当たった」を判定する（`_onCut` は `_targets` が 0 だと呼ばれない）
