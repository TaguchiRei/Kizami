- 作業の前に、スキル `overall-section-plan`・`planning-criteria`、`Assets/Docs/InGame/TechnicalPremises.md`、`.claude/docs/NotionSpec.md` を読む

- リスクや懸念には、コードの箇所・仕様書・計測値の根拠を付ける。根拠のないものは「確認したいこと」としてユーザーに聞く（planning-criteria の基準4）
- 仕様の変更は行わない。Notion の仕様と計画書が食い違っていたら、どちらに合わせるかをユーザーに聞く
- Git 操作はユーザーが行う
