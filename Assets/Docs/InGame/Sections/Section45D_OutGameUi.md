## 目的

アウトゲームの画面とボタンを、AI に作らせた仮のものから、見せられる見た目にする。区間42（アルファ版の UI）のデザインとプレハブ化を、この区間で先に行う。区間42 の画面の遷移の演出（42-3）と、インゲームの HUD（44-6）は扱わない。

## 既存コードの確認結果（2026-10-26）

| 場所 | 今の状態 |
|---|---|
| `OutGameMenuAdapter`（`EngineAdapterLayer/OutGame/`、540 行） | ホーム・ステージ選択・スキル装備・解放の演出を、初期化のときにコードで 1 つの Canvas に組み立てる。ボタンは 720×90 の単色の四角で、画面の中央に縦に並べる。色は SerializeField の 4 色 |
| `ConfigScreen`（同、215 行）・`InputRebindAdapter`（178 行） | コンフィグの画面とキーの割り当て。コードで組み立てる |
| `UiBuilder`（`EngineAdapterLayer/UI/`、170 行） | コードで UI を組む共通の部品。文字は旧 uGUI の `Text` で、フォントは組み込みの `LegacyRuntime.ttf`（日本語は OS のフォントで代わりに出る）。インゲームの HUD・リザルト・ポーズもこれで組む |
| パッケージ | `com.unity.ugui` 2.0.0（TextMesh Pro を含む） |
| フォント | プロジェクトに日本語のフォントのアセットは見当たらない。HUD で「刃術」が「刀術」と出るのは、フォントの都合で意図したもの（不具合として直さない） |

## 作業計画

デザインはユーザーが決めるので、最初のコミットの前に止まる。

| 段階 | 内容 | 止まる所 |
|---|---|---|
| 1 調べる | 今のアウトゲームの画面（ホーム、ステージ選択、スキル装備、コンフィグ、解放の演出）を、プレイモードで 1 枚ずつ撮る（uloop の screenshot）。画面ごとに「何がまずいか」（文字の大きさ、配置、余白、ボタンの見た目、状態の見分け方）を一覧にする | 撮った画像と一覧を報告する |
| 2 方向を決める | デザインの方向の案を 2〜3 個出す（参考にする画面の雰囲気、色、フォント、ボタンの形と、押せる・選んでいる・押せないの見分け方）。HTML のモックや画像で見せてもよい | ユーザーが方向を決めるまで実装しない |
| 3 部品を作る | 決めた方向で、ボタン・見出し・パネルの部品をプレハブにする。文字は TextMesh Pro にし、日本語のフォントのアセットを作る（フォントはライセンスを確かめ、ユーザーに確認してから入れる） | ボタン 1 つを実機で見せて確かめる |
| 4 画面を移す | 画面ごとに、コードで組んでいる部分をプレハブに移す。`OutGameMenuAdapter` と `ConfigScreen` は、プレハブの参照を持ち、表示の更新と入力の受け渡しだけをする形にする。画面 1 つごとにコミットを分ける | 画面ごとに報告する |

## 完了条件

- ホーム → ステージ選択 → インゲーム → アウトゲームへ戻る流れを、新しい UI で通して操作できる
- スキル装備とコンフィグが、新しい UI で今と同じように使える
- ボタンの「押せる・選んでいる・押せない」が見分けられる
